# VibeLock Vault Format Specification (`.vibe`)

> Version: 1
> Status: Draft
> Purpose: Define the canonical format of the `.vibe` file so that any SDK (TypeScript, Python, Java) can read/write secrets interoperably.

---

## 1. File Structure

The `.vibe` file is a JSON document with the following top-level schema:

```json
{
  "version": 1,
  "projectId": "test",
  "keysPath": "/etc/vibelock/keys",
  "env": {
    "SERVER_URL": "http://localhost:3000",
    "LOG_LEVEL": "INFO"
  },
  "secrets": {
    "API_KEY": {
      "iv": "<hex>",
      "tag": "<hex>",
      "ciphertext": "<hex>",
      "salt": "<hex>"
    }
  }
}
```

| Field        | Type   | Description                                      |
| ------------ | ------ | ------------------------------------------------ |
| `version`    | number | Schema version. Currently `1`.                   |
| `projectId`  | string | Optional. Project identifier for master key resolution. |
| `keysPath`   | string | Optional. Custom base directory for master key storage. |
| `env`        | object | Optional. Map of non-secret environment variables (plaintext). |
| `secrets`    | object | Map of secret name → encrypted payload.          |
| `iv`         | string | Hex-encoded initialization vector (12 bytes).    |
| `tag`        | string | Hex-encoded GCM authentication tag (16 bytes).   |
| `ciphertext` | string | Hex-encoded encrypted value.                     |
| `salt`       | string | Hex-encoded PBKDF2 salt (16 bytes).              |

---

## 2. Encryption Algorithm

- **Cipher**: AES-256-GCM (Galois/Counter Mode)
- **Key size**: 256 bits (32 bytes)
- **IV**: 12 bytes, randomly generated per encryption operation
- **Authentication tag**: 16 bytes (128 bits)

---

## 3. Key Derivation

- **Function**: PBKDF2
- **Hash**: SHA-512
- **Iterations**: 600,000
- **Salt**: 16 bytes, randomly generated per secret
- **Derived key length**: 32 bytes (256 bits)

The derived key is computed as:

```
derivedKey = PBKDF2-SHA512(masterKey, salt, 600_000, 32)
```

---

## 4. Master Key

- **Size**: 32 bytes (256 bits), cryptographically random
- **Storage**: File-based at a configurable path
- **Permissions**: `chmod 600` (owner read/write only)
- **Format**: Raw binary file (not hex or base64 encoded)

The master key path is resolved in this order:

1. Explicit option (SDK `keysPath` / CLI `--keys-path`)
2. Environment variable `VIBELOCK_KEYS_PATH`
3. `keysPath` field from the vault file
4. Default: `~/.vibelock/keys/<projectId>/master.key`

The master key MUST be stored outside the project directory to prevent accidental commits.

---

## 5. Encoding

All binary fields in the `.vibe` JSON file use **lowercase hexadecimal** encoding:

| Field        | Raw size | Hex length |
| ------------ | -------- | ---------- |
| `iv`         | 12 bytes | 24 chars   |
| `tag`        | 16 bytes | 32 chars   |
| `salt`       | 16 bytes | 32 chars   |
| `ciphertext` | variable | variable   |

---

## 6. Encryption Flow

The encryption process is divided into three layers of responsibility: **Provisioning**, **Derivation**, and **Encryption**. The `salt` must be generated by the orchestrator (Phase 2) before invoking the cryptographic functions defined in Phase 1.

### Step-by-Step Process:

1.  **Master Key Retrieval**: The system retrieves the 32-byte `masterKey` from the file-based provider at the resolved path.
2.  **Metadata Generation (App Layer)**:
    - The system generates a **random 16-byte `salt`**.
    - *Note: This salt is unique per secret and must be stored in the final JSON.*
3.  **Key Derivation**:
    - Invoke `crypto.deriveKey(masterKey, salt)`.
    - This returns the 32-byte `derivedKey`.
4.  **AES-GCM Encryption (Crypto Layer)**:
    - Invoke `crypto.encrypt(derivedKey, plaintext)`.
    - The module internally generates a random **12-byte `iv`**.
    - The function returns: `{ iv, tag, ciphertext }` (hex encoded).
5.  **Persistence**: The system assembles and saves the four fields (`iv`, `tag`, `ciphertext`, `salt`) as hex strings in the `.vibe` file.

## 7. Decryption Flow

1. Read the master key from the file at the resolved path (`~/.vibelock/keys/<projectId>/master.key` or custom).
2. Read the secret entry from the `.vibe` file.
3. Decode `salt`, `iv`, `tag`, and `ciphertext` from hex.
4. Derive the key: `derivedKey = PBKDF2-SHA512(masterKey, salt, 600_000, 32)`.
5. Decrypt: `plaintext = AES-256-GCM-Decrypt(derivedKey, iv, ciphertext, tag)`.
6. If the tag verification fails, reject the value (data may have been tampered with).
